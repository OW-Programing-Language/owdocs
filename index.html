Overview

OW is an open-source programming language with indentation-based, YAML-inspired syntax. The Java-hosted distribution includes an interpreter, LLVM IR backend for an experimental native subset, CLI and bundled OwIDE. The interpreter runs object-oriented applications, modules and functors, web APIs, interactive UIs, tests and more.

What changed: OW gained classes, typed functions, imports, arrays and maps, floats, contracts, module calculus, OWUnit, exceptions, external dependencies, persistence and rapidly expanding native collections support.

OW is real code, not a YAML configuration parser. Start with ow run for the broadest feature support.

Installation

Download OW from the installation guide or GitHub Releases. Windows installer and portable runtime-bundled builds do not require separately installing Java. JVM distributions require Java 17+.

ow version
ow help
ow ide
ow run examples/oop_demo.ow

To build the language from source, use JDK 17+ and Maven:

git clone https://github.com/OW-Programing-Language/ow-lang.git
cd ow-lang
mvn clean package
java -jar target/OwIDE.jar help
Do not download the old downloads/OwIDE.jar link from previous documentation; release assets are published on GitHub. ow build also requires Clang/LLVM or Zig on the host.

Your first program

Save this as hello.ow. The top-level main: block runs the program and fn declares a reusable function:

fn greet(name: string):
  returns: string
  return: "Hello, " + name + "!"

main:
  set who: "OW"
  print: greet(who)
ow run hello.ow
# Hello, OW!

Use a consistent two-space indentation for all nested blocks. # begins a comment.

Syntax and indentation

OW combines keyword: value statements and indentation-defined blocks. No semicolons or braced statement blocks are needed.

# comment
main:
  set value: 2
  if: value > 1
    print: "greater"
  else:
    print: "smaller"

Top-level constructs include fn, class, enum, interface, model, module_type, module, functor, import and main:. Declarations and expressions are validated by the OW parser, not YAML tools.

Types, values and arithmetic

The interpreter supports integers, IEEE-754 floats, strings, booleans, arrays, records/maps, enums, class instances and module values. set declares or reassigns a variable, optionally with a type.

main:
  set count int: 10
  set label string: "score"
  set enabled bool: true
  print: label + ": " + str(count)
  print: 7 / 2       # 3 (integer)
  print: 7.0 / 2     # 3.5 (float)

Operators include + - * / == != < <= > >=. Integer-only division remains integer; arithmetic with a float promotes to floating-point. Convert with int, floor, ceil and round.

Control flow

OW supports if:/else:, else if, while:, and switch: with case/default:. A case can match several values.

main:
  set x: 2
  switch: x
    case 1:
      print: "one"
    case 2, 3:
      print: "two or three"
    default:
      print: "other"
  set i: 0
  while: i < 3
    print: i
    set i: i + 1

For native code, control-flow syntax is supported only when its expressions use natively supported types and operations.

Functions and typed signatures

The preferred YAML-style signature uses name: type parameters and a returns: type declaration at the start of the function body. The return: statement returns the actual value; call: discards a call result.

fn add(a: int, b: int):
  returns: int
  return: a + b

main:
  print: add(20, 22)

Legacy fn add(a int, b int) -> int: and untyped fn add(a, b): still work. Never combine an arrow return type and a body returns: declaration in the same function. Native reference-counted values need explicit types at function boundaries.

Arrays and dictionaries

Arrays

main:
  set scores: [4, 8, 12]
  set scores[1]: 9
  set zeros: array(3, 0)
  print: scores[1]
  print: len(zeros)

Dictionaries and records

String-keyed maps preserve insertion order. Identifier keys also support dot access; direct missing-key indexing raises an error.

main:
  set profile: { name: "Ada", level: 3 }
  set profile["level"]: 4
  print: profile.name
  print: map_get(profile, "missing", "default")
  print: map_keys(profile)[0]

Map builtins: map_get (lazy fallback), map_has, map_set, map_delete, map_keys, map_values, map_size. Native map value types are more restricted than interpreter values.

Object-oriented programming

Classes support fields, the new constructor, instance methods and this. OW also has private/public members, inheritance, overrides, dynamic dispatch, enums and to_string().

class Person:
  field name
  fn new(value):
    set this.name: value
  fn hello():
    return: "Hi " + this.name

class Friend(Person):
  fn hello():
    return: "Hey " + this.name

main:
  set friend: new Friend("Ada")
  print: friend.hello()

Full OOP execution is interpreter-backed; general classes and object graphs are not yet LLVM-native.

Interfaces and contracts

interface declares an object's public method contract. OW checks implementations before main:: missing methods, private replacements, wrong arities, incompatible typed signatures and inheritance cycles are rejected.

interface Storage:
  fn put(key: string, value: int):
    returns: bool

class MemoryStorage(Storage):
  fn put(key: string, value: int):
    returns: bool
    return: true

Type annotations are optional but validated where present. This contract system is not a complete whole-program inference engine.

Module types, functors and abstract types

OW implements a tested subset of OCaml-inspired module calculus: module_type, module, functor, functor_gen, structural signature matching, opaque/manifest types, with_type sharing, aliases, nested modules, include, higher-order functors and first-class packages (pack/unpack).

module_type COUNTER:
  fn get() -> int

module Answer: COUNTER
  fn get() -> int:
    return: 42

main:
  print: Answer.get()

Public exports are sealed to declared signatures. Applicative functors preserve stable abstract-type identities; generative functors create fresh identities. ow check validates known module contracts without running main:.

Projects, imports and boundaries

import "relative/file.ow" loads other OW files relative to the importing file. The entry file can hold main:, while components live in separate files. Missing imports and cycles are detected.

# src/main.ow
import "api/Math.ow"

main:
  print: add(5, 6)

Layouts using api/ and infra/ get enforced import boundaries. An API cannot import infrastructure, and one module cannot directly import another module's private infrastructure. The composition root may wire implementations together.

shop/
  main.ow
  inventory/api/InventoryApi.ow
  inventory/infra/Inventory.ow
  orders/api/OrdersApi.ow
  orders/infra/Orders.ow

This convention is relevant to the separate flOW framework.

Dependency management

A project-root dependencies.yml defines Git repositories and versioned OW source-library aliases. dependencies.lock.yml records resolved commits; installed sources are cached under .ow/deps/.

format: 1
repositories:
  - id: github
    url: https://github.com
dependencies:
  - name: math
    repository: github
    path: OW-Programing-Language/ow-math-questions
    version: c22d01cfee6be18d96d4c55b95b7e79892bca9f6
ow deps init
ow deps install
ow deps list
ow deps update
# import "@math/src/MathQuestions.ow"

Commit the manifest and lockfile; gitignore .ow/deps/. run, check, llvm, build and package resolve the nearest manifest. This is for direct OW source dependencies—not Maven packages, semver ranges or transitive dependency solving.

OWUnit and test runner

The interpreter discovers @Test, @BeforeEach and @AfterEach on zero-argument test functions and class methods. No main: is required. Class-based tests instantiate a new object for each test.

class CalculatorTest:
  field value
  @BeforeEach
  fn setup():
    set this.value: 2
  @Test
  fn addsNumbers():
    call: assert(this.value + 3 == 5, "wrong result")
  @AfterEach
  fn cleanup():
    set this.value: 0
ow test examples/owunit/CalculatorTest.ow
ow test tests/
ow test tests/CalculatorTest.ow --filter CalculatorTest.addsNumbers

Directory discovery matches *Test.ow and *_test.ow. A failure exits nonzero. The separate OWUnit repository offers additional assertions. Native LLVM does not run annotated tests.

Exceptions and assertions

throw: raises an OW runtime exception. try: requires catch name: and/or finally:. The catch variable holds the error message; finally runs even on returns and errors. Failed assert(...) calls are catchable in the interpreter.

main:
  try:
    throw: "bad input"
  catch message:
    print: "Caught " + message
  finally:
    print: "cleanup"

Native compilation does not yet lower try/catch/finally; native array bounds and missing-map-key failures abort rather than throwing catchable OW errors.

Save/load and JSON

save(path, value) writes JSON (creating parent folders). load(path) restores JSON or returns 0 when missing; exists(path) distinguishes missing files. json and json_parse work in memory.

main:
  set path: "save/player.json"
  if: exists(path)
    set player: load(path)
    print: player.name
  else:
    call: save(path, { name: "Ada", level: 1 })

Paths are relative to the working directory in normal runs and to packaged resource locations according to packaging rules.

Built-in model tables

A model declaration creates an auto-persisted table in ow-data.json, without an external SQL server. Customize its path with OW_DB_PATH or ow.db.path.

model Task:
  title string
  done bool

main:
  save Task: {title: "Write docs", done: false}
  set open: find Task where done == false
  print: len(open)
  delete Task where done == true

find Model reads all records; find Model where condition filters; save Model: inserts with automatic IDs; delete Model removes rows.

HTTP server and routes

The interpreter can serve HTTP routes without an external server framework. Combine route, respond: and serve: for JSON or text APIs.

main:
  route "GET /health":
    respond: {ok: true}
  route "GET /hello/:name":
    respond: {greeting: param("name")}
  serve: 8080

Helpers include param, query, body, body_json and response(status, payload). The request also exposes a req record. Explore Night for a separate higher-level OW web framework.

Web and native-window UI

OW renders a shared widget tree in a browser (ui_run or ui_run_web) or desktop window (ui_run_native). Buttons and input fields dispatch to functions or instance methods.

fn view():
  return: ui_col([
    ui_heading("Counter"),
    ui_text("Count " + str(count)),
    ui_button("+1", "increment")
  ])
fn increment():
  set count: count + 1
main:
  set count int: 0
  call: ui_run("view", "OW Counter")

Widgets include ui_heading, ui_text, ui_button, ui_input, ui_image, ui_bar, ui_space, ui_card, ui_backdrop, ui_row, ui_col, ui_grid and ui_disc. Use ui_stop to stop the UI.

Set OW_UI_MODE to select a backend; OW_UI_NO_BROWSER=1 prevents browser auto-launch.

LLVM native compilation overview

ow llvm emits LLVM IR and ow build compiles supported constructs to a standalone executable without a JVM. The compiler itself still requires Java. This is an experimental, incomplete subset, not full OW interpreter parity.

ow llvm examples/native_dynamic_strings.ow target/strings.ll
clang target/strings.ll -o target/strings
./target/strings

Native support includes procedural integer operations, typed function boundaries, UTF-8 strings, reference-counted integer/string arrays, specialized string-key dictionaries, nested native maps, ordered map snapshots and statically resolvable integer-only module/functor calls.

General classes, object graphs, floats, OWUnit, try/catch, database models, HTTP and UI runtimes remain interpreter-only. Unsupported operations must not be assumed to compile natively.

Native strings, arrays and ARC

Native string values can be UTF-8 literals or dynamic string + string concatenations. Comparisons are content-based; len(string) counts UTF-16 code units like the Java interpreter. Embedded NULs are unsupported.

fn make(size: int):
  returns: string_array
  return: array(size, "Hello " + "OW")

main:
  set names: make(3)
  print: names[0]
  print: len(names)

array (i32 integer arrays) and string_array support indexed mutation, dynamic construction, typed arguments/returns and ARC ownership. String arrays release child strings when their last owner exits. [] is an empty integer array; use array(0, "") for an empty native string array.

Reference counters are currently single-threaded, the ABI is experimental and bounds errors abort in native programs.

Native maps, nested values and iteration

Native dictionaries specialize string-keyed values as int_map, string_map or mixed_map (tagged integer, string and nested-map values). A resizing UTF-8 hash table provides average O(1) lookup.

main:
  set cfg: {name: "OW", version: 6}
  set keys: map_keys(cfg)
  set values: map_values(cfg)
  print: keys[0]
  print: cfg["name"]

map_keys/map_values create owned, insertion-ordered snapshots. Updating a key preserves its position; deleting and reinserting moves it to the end. mixed_map value snapshots use mixed_array.

Nested maps are managed by ARC with cycle prevention. Native maps do not yet cover arbitrary classes, floats, null, arrays as map values or full JSON lowering. Invalid native lookups may abort.

Native module/functor subset

The LLVM backend can lower some statically resolved integer module and functor calls, including documented qualified, opaque and packed static cases. It is not a general OCaml-compatible module compiler.

ow check examples/module_calculus/native_llvm.ow
ow llvm examples/module_calculus/native_llvm.ow target/native-modules.ll

ow check passing does not guarantee that ow llvm can compile a file: dynamically computed first-class modules and arbitrary higher-order functors remain interpreter-first.

OwIDE and OWler-IDE

Bundled OwIDE is a Java desktop editor with project browsing, run/build actions and web/native UI launch controls. Use ow ide or the desktop launcher supplied in Releases.

OWler-IDE is a separate Tauri/Rust/React IDE project. Its features, installers and release maturity should be checked in that repository; do not confuse its capabilities with the bundled Java OwIDE.

Troubleshooting

  • ow not found: add the release bin/ to PATH, or run the JAR.
  • Java class version error: use Java 17+ or the runtime-bundled installer.
  • Native compiler missing: install LLVM/Clang or Zig; ow run does not need them.
  • Native unsupported type: try the interpreter and check the precise native feature page.
  • Unresolved @alias: run ow deps install, inspect the manifest and lockfile.
  • Test not discovered: filename must end with Test.ow or _test.ow.
  • Import boundary failure: depend on public api/, not another module's infra/.
  • Speech model missing: download a Vosk model and provide its directory explicitly.

When filing a bug, share a minimal source example and identify which of ow run, ow check or ow llvm fails.
